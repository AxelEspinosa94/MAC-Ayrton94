# 1.1 Industrial Revolution: Analytical Approach  

### **Exercise 1.1.1 — Analytical Thinking**
Explain how the analytical approach of the Industrial Revolution influenced:
1. Manufacturing processes  
2. Organizational structure  
3. Early optimization methods  

Provide one historical example for each.

1. **Mechanistic worldview:** Org as machine → modern example: call centers with strict scripts.  
2. **Determinism:** If process known, output predictable → modern example: automated production lines.  
3. **Linear causality:** Input changes → proportional output change → simple budgeting models.  
4. **Specialization:** Narrow roles → modern example: micro-specialized dev teams (frontend/backend).

---

### **Exercise 1.1.3 — Reductionism vs. Holism**
Compare reductionism and holism using:
1. A mechanical system (e.g., engine)  
2. A social system (e.g., school)  
3. A biological system (e.g., ecosystem)

Explain why reductionism fails in complex systems.

1. **Engine:** Reductionism works—components (pistons, valves) can be optimized individually.  
2. **School:** Fails—optimizing one teacher or one class doesn’t guarantee better overall education.  
3. **Ecosystem:** Fails—changing one species affects entire food web.  
Reductionism fails when interactions and feedback dominate behavior.

# 1.2 Postindustrial Revolution: Systems Approach  
### **Exercise 1.2.1 — Systems Thinking**
Describe how the shift from the analytical paradigm to the systemic paradigm changed:
1. Decision-making  
2. Organizational design  
3. Optimization strategies

1. **Decision-making:** From local metrics (cost, speed) to global impact (sustainability, resilience).  
2. **Organization:** From rigid hierarchies to networks, cross-functional teams.  
3. **Optimization:** From single-objective to multi-objective, considering trade-offs and interactions.

---

### **Exercise 1.2.2 — Systems Era Doctrines**
Explain the doctrines of the “Systems Era”:
- Holism  
- Interdependence  
- Feedback  
- Emergence  

Provide an example of each in a real-world system.

1. **Holism:** Company reputation emerges from all departments, not just marketing.  
2. **Interdependence:** Supply chain nodes depend on each other (suppliers, distributors).  
3. **Feedback:** Recommendation systems adjust based on user behavior.  
4. **Emergence:** Traffic patterns emerge from individual driver decisions.

---

### **Exercise 1.2.3 — Nonlinear Interactions**
Give three examples of systems where:
1. Local optimization harms global performance  
2. Interactions are nonlinear  
3. Feedback loops dominate behavior  

Explain why linear models fail in these cases.

1. **Local optimization harms global performance:**  
   - Over-optimizing one warehouse’s inventory can increase total logistics cost.  
2. **Nonlinear interactions:**  
   - Network congestion: small increase in traffic → huge delays.  
3. **Feedback-dominated:**  
   - Social media engagement loops.  
Linear models fail because effects are disproportionate and path-dependent.

# 1.3 Concept of a System  
### **Exercise 1.3.1 — System Identification**
For each scenario, identify:
- System boundary  
- Inputs  
- Outputs  
- Components  
- Environment  

Scenarios:
1. A hospital
   - Boundary: hospital building/services.  
   - Inputs: patients, staff, supplies.  
   - Outputs: treated patients, reports.  
   - Components: ER, surgery, labs.  
   - Environment: health regulations, community.
2. A public transportation network
   - Boundary: network of buses/trains.  
   - Inputs: vehicles, fuel, passengers.  
   - Outputs: trips completed.  
   - Components: routes, stations.  
   - Environment: city layout, traffic laws.
3. A video game engine
   - Boundary: engine codebase.  
   - Inputs: user input, assets.  
   - Outputs: rendered frames, audio.  
   - Components: physics, rendering, AI.  
   - Environment: hardware, OS.

---

### **Exercise 1.3.2 — System Properties**
Explain how each property defines system behavior:
1. Structure  
2. Dynamics  
3. Feedback  
4. Purpose  

Provide examples for each.

1. **Structure:** How components are arranged (e.g., layered architecture).  
2. **Dynamics:** How state changes over time (e.g., queue lengths in a system).  
3. **Feedback:** Outputs influencing future inputs (e.g., load balancing).  
4. **Purpose:** Goal (e.g., minimize latency, maximize profit).

# 1.7 Operations Research (OR): Origin, Development, Meaning  
### **Exercise 1.7.1 — Historical Development**
Explain how Operations Research emerged during WWII.  
Identify:
1. The original problems it solved  
2. The techniques used  
3. Why OR expanded after the war  

1. **WWII problems:** Radar placement, convoy routing, resource allocation, anti-air defense.  
2. **Techniques:** Linear programming, queuing theory, simulation, game theory.  
3. **Post-war expansion:** Applied to industry, transportation, telecom, health, finance.

---

### **Exercise 1.7.2 — OR Problem-Solving Process**
Apply the OR methodology to a real-world problem:
1. Formulate the problem  
2. Build a model  
3. Solve it (conceptually)  
4. Validate the model  
5. Implement the solution  
6. Monitor results  

1. Formulate: minimize total cost (transport + facility).  
2. Model: location-allocation model (LP or MILP).  
3. Solve: use optimization solver.  
4. Validate: compare with historical data, sanity checks.  
5. Implement: choose sites, adjust operations.  
6. Monitor: track costs, service levels, adjust model.

---

### **Exercise 1.7.3 — OR vs Systems Theory**
Explain how Operations Research is:
1. A mathematical extension of systems theory  
2. A practical tool for decision-making  
3. A foundation for modern optimization  

Provide examples.

1. **Mathematical extension:** OR turns systems concepts into formal models (LP, networks, stochastic models).  
2. **Practical tool:** Used for scheduling, routing, inventory, resource allocation.  
3. **Foundation for optimization:** Many modern algorithms (e.g., simplex, interior point, heuristics) come from OR.

Examples: airline scheduling, traffic assignment, production planning.
